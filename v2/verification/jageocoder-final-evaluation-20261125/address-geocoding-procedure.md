# 住所による座標取得の標準手順

1. **入力を固定する。** 元住所、照会用住所、安定したID、基準日、期待する市区町村コードを保持する。政令指定都市は区まで扱う。住居表示と地番を含む住所体系、辞書版、取得日時、座標軸と測地系、利用条件を記録する。
2. **元表記で照会する。** ABR・CSIS・Jageocoderなどの住所照会を使う。Jageocoderでは座標必須と正規化用を同じ入力で実行し、照合した原文と未照合部分、候補全件、辞書階層、有効な座標を保存する。対象のIDと入力が全方式の出力から追えることを確認する。
3. **座標が指す階層を判定する。** 住所階層と未照合部分から、自治体、町字・丁目、親番・街区、入力の番地・号を判定する。未照合の枝番・号や複数地番が残る場合は、より粗い対応範囲を表示する。座標なしの末端ノードを照合できても、地図上の点は実際に座標を持つノードの階層で扱う。
4. **行政区域と競合を監査する。** 期待コードの境界ポリゴンで包含を確認し、区域外は境界までの距離も記録する。候補を座標で重複整理し、近隣の別候補との距離、異住所が同一点を指す例、比較する座標の粒度を確認する。同じ原典に由来する近接点は相互確認の強さを割り引く。別の座標を返す同等候補は近接点の閾値を事前に定め、衝突時は保持中の採用案を維持して審査する。
5. **正規化を差分で試す。** 元の表記を保存し、根拠があるときに空白、数字幅、ダッシュ、枝番区切りを一つずつ変更する。自治体の正字や改称、付記の切り分けは公式な住所情報に照らす。数字の追加・削除や住居表示と地番の読み替えを推測で行わない。各表記は別の照会IDとし、元IDへ戻せるようにする。
6. **詳細化と精度低下を区別する。** 期待区域、番号の対応、候補競合、異住所共有を再確認し、元の採用案より詳しい座標だけを変更候補とする。対応範囲が同等なら従来点を優先する。大きく移動する点は、辞書階層と照会文字列の対応を確認して保留条件を明示する。
7. **受け渡し前に照合を完結させる。** 1行1IDの採用案、変更一覧、候補と保留の根拠、精度・原因別の未解決、出典・利用条件を保存する。未解決原因は複数付け、件数の母数にはユニークIDを使う。公開時は座標の精度を明示し、住所で取得した点にはその対応範囲を超える精度を付与しない。

本件の照会対象は住所。店舗・施設名による位置検索とGoogle Mapsからの座標取得は行わない。 [ABR利用規約](https://www.digital.go.jp/policies/base_registry_address_tos) · [CSIS利用条件](https://geocode.csis.u-tokyo.ac.jp/home/csv-admatch/#terms-of-use) · [Jageocoder利用条件](https://jageocoder.info-proto.com/license) · [国土数値情報 N03](https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-N03-2026.html)
