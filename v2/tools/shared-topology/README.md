# 全国共通TopoJSON生成基盤（試作）

作成日：2026-11-01。**現行サイトの地図表示にはまだ接続していません。**

## 目的

現在の `v2/data/national/2021/{pref}.topojson` は都道府県ごとに簡素化された試験データです。県境の座標が左右で数十〜数百m異なることがあり、府県の外郭線を別々に描画すると二重線やずれが起こります。

**全国で1つのGeoJSONを基に、全国一括で位相（Topology）を構築・簡素化し、その後で都道府県別ファイルに切り分けます。** 共通アークの座標配列は各府県ファイルで同一に保つため、府県境を一致させられます。市区町村のポリゴン、複数リング、離島や飛び地は保持します。

## 入力の正本

国土交通省「国土数値情報・行政区域 N03」**2026年1月1日時点（2026年4月公表）**。

- 公式ページ： https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-N03-2026.html
- 全国の圧縮データ：`N03-20260101_GML.zip`（約766MB）。
- 形式：公式配布ZIPから、全国一括で抽出・変換した**GeoJSON FeatureCollection**。
- 各Featureの `properties.N03_007` に5桁地域コード、`N03_004` に区域名が必要です。
- 全国一括のファイルを使用します。都道府県ごとの旧TopoJSONを接合したものを入力にしてはいけません。それだけでは根本的な境界ずれが直りません。
- 出典・ライセンス：国土数値情報（国土交通省）、CC BY 4.0。原典に国土地理院由来情報があり、公開・複製には別途申請が必要な場合があるため、配布前に利用条件を確認してください。

公式の元データに暫定境界・未確定区域がある場合は、それを隠さず記録します。公式データ自体が不整合であれば、量子化だけで解決するとは限りません。

## オフラインでの実行方法

大きな全国データはPC上で一度処理します。閲覧者のiPhoneには完成した軽量な地図データのみ配信します。

1. Node.js 20以降を用意
2. 国土交通省の全国ZIPを取得して展開し、GDAL等のGISツールで全国一括GeoJSONに変換
3. このフォルダで `npm install`
4. 最初に `npm test` （合成された大阪・奈良の2府県・4自治体で共通境界と飛び地の保持を確認）
5. 試験データを生成：

```sh
node build.mjs --input /path/to/n03-2026-all.geojson --output ./generated \
  --quantization 1000000 --keep 0.02 --expect-prefectures 47
```

出力：`generated/01.topojson` … `47.topojson` と `generated/manifest.json`。各府県ファイル内の共有アークは全国一括生成されたアークをそのままコピーします。量子化も簡素化も府県別には行いません。

`--keep 0.02` は頂点を概ね2%残す**初期検討値**で、実際の完成品に適切かは未検証です。読みやすさ優先で飛び地や細い領域が欠けないか、1%、2%、5%などを比較して選択してください。生成スクリプトは小さな島を削除するフィルターを使いません。

## 自動検査

`npm test` で以下を検査します。

- 大阪側・奈良側が**同じ座標配列の共有アーク**を持つ
- 全国生成・都道府県抽出で共有アークが変わらない
- 飛び地が消えない
- 市区町村コード欠損のあるFeatureを黙って削除せず、生成を停止する

生成時の `manifest.json` には府県ペアごとの共有アーク数を記録します。大阪・奈良の両方が入力にあるのに共有アークが0本なら生成を停止します。

## 本番投入前の追加監査（未実施）

1. 2026年原本の47都道府県の町名・区名・コード件数と一致するか。
2. 県境ごとの共有アーク数が適切か。接するはずの県で0本なら調査。
3. ポリゴンの欠損、重なり、隙間がないか。境界未確定地・水面等は例外を明示。
4. 面積の変化・細長い市町村・離島・飛び地・穴の保存を確認。
5. 神戸市中央区、田尻町の**新案5C**ラベル位置、選択判定、表示の安定性を再確認。
6. 柏原市・三郷町、太子町・香芝市で府県境が1本になるか。
7. 各県での読み込み性能、スマートフォンの操作性、権利表示。
8. 府県別出力が現在のV2レンダラーの形式と合うか、ステージングで検査した後にのみ切替。

## 注意

- **生成基盤だけを追加する段階**です。2026年の全国N03の実ファイルは、このリポジトリに追加していません。まだ全国共通の地図ファイルそのものは生成していません。
- 現行 `density.html` と `density-app.js`、2021年のデータ、庁舎JSON、新案5Cは一切変更しません。
- 全国の元GeoJSONは巨大なため、変換・検証には十分なPCメモリが必要です。
- 既存の小さな比較試作（画素、共通ベクター）は残します。本採用は上の監査が合格してからです。
