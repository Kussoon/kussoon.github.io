# 芦屋市 V2：読み仮名と1行上下微調整の比較（2026-10-30）

試験ページ：[`/v2/ashiya/readings.html`](../ashiya/readings.html)  
本体プログラム：[`/v2/common/js/readable-labels.js`](../common/js/readable-labels.js)

## 目的と背景

地名には読みの例外が多い。ユーザーが指摘した西宮市「美作町」は「みさくちょう」であり、一般的に連想しやすい「みまさかちょう」ではない。このため、地図は場所だけでなく**正しい読みも覚える教材**とする。

Yahoo!マップの住所レイヤーを参考に、地名自体は原則1行で表示し、縮尺によるラベルの選択と「上下へ半文字・1文字程度動かす」方式を試す。同時に「漢字のみ」「漢字＋小さな読み仮名」「ひらがなのみ」を切り替えられるようにする。

これはYahoo!マップの地図・アプリ・有料コンテンツを複製するものではなく、UI設計の参考にした独立実装である。

## 読み仮名データの出典と一致確認

- `Kussoon/ashiya` の既存 `town-search.html` には `{name,reading}` が**59件**あり、`/v2/data/ashiya/labels-source.json` の59町名と**59対59で完全一致**する。
- 読み仮名は**すべてひらがな**であり、欠落0件、重複0件。
- 読みの既存照合資料は日本郵便「郵便番号検索」。出典は [SOURCE_LEDGER.md](https://github.com/Kussoon/ashiya/blob/main/SOURCE_LEDGER.md) に記録。
- `v2/data/ashiya/readings.json` に地理形状と別に保存。元Git blob SHAを出典メタデータに記録する。
- 「業平町＝なりひらちょう」「大桝町＝おおますちょう」「剱谷＝けんたに」などの現行データをそのまま使用。
- 学習用地図の境界にはCODH由来の加工SVGを使用。形状・読みは別データ。今後新たな市に展開する際は読みの照合元を市ごとに点検する。
- 芦屋市の試作では町名をJSONキーにしているが、V2の汎用データ設計では**同名町の存在に備えて安定した地域ID**に移行すること（設計上の課題として残す）。

## 比較内容

| 表示モード | 地名ラベル | 文字寸法 |
| --- | --- | --- |
| 漢字のみ | 漢字地名を1行 | 画面上12～22 CSS pxから選択 |
| 漢字＋小さな読み仮名 | 漢字1行＋その下に小さなひらがな1行 | 漢字の約58％の文字サイズで読みを追加 |
| ひらがなのみ | 読み仮名を1行 | 画面上12～22 CSS pxから選択 |

「漢字＋読み仮名」は、**地名を意味的に2分割した2行表示とは別**。町名自体の改行はしない。

上下の微調整：基準のラベル中心を維持するか、重なる場合に上・下へ半文字／1文字／1.5文字分の候補を試す。横方向には動かさず、候補中心が対応する区域内に留まることを条件とする。衝突回避後も重なるラベルは縮尺に応じて一時的に非表示にできる。

文字寸法は画面の描画幅とSVG viewBoxを使ってCSSピクセルから変換する。漢字・読み仮名を合わせたラベル矩形を衝突計算に含め、漢字だけの高さで判定しない。

町名検索は漢字・ひらがな・カタカナ（NFKC正規化）に対応。検索語はブラウザ内でのみ処理し、ネットワーク送信しない。ラベルが省略されていても検索・地図選択から到達可能。

## ブラウザではない予備計算

59町名、全域表示、画面幅390 CSS px、文字16px、文字幅を1文字≒フォントサイズと仮定：

| 表示方式 | 上下調整なしの表示件数 | 上下微調整ありの表示件数 |
| --- | ---: | ---: |
| 漢字のみ | 24 | 25 |
| 漢字＋読み | 17 | 20 |
| ひらがなのみ | 18 | 21 |

この予備条件では表示中ラベル矩形の重複は0組。**ブラウザの日本語フォント寸法・描画結果・性能を保証する数値ではない。** また上下への微調整は「区域外」判定を改善する目的ではなく、他ラベルとの衝突を回避するための方法である。

## 実機での確認ポイント

1. 全域表示で、漢字のみ／漢字＋読み／ひらがなを切り替え、文字の大きさと読みやすさを確認。
2. 「上下移動なし」と「上下微調整」を同じ表示範囲で比較。とくに市街地密集部のラベル数・位置を観察。
3. 2～4倍に拡大し、表示する名前が増えるか、読みと漢字の対応がずれないかを確認。
4. 「なりひらちょう」「オオマスチョウ」の入力から検索・該当町選択・拡大が機能するか確認。
5. ピンチ、ドラッグ、PCホイールのB案と地図外クリックを確認。
6. 文字が区域からはみ出す赤文字判定だけで表示品質を決めない。重要なのは読みやすさ、位置の特定しやすさ、ラベル同士の重なり、全地名への到達性。

## 限界・次工程

- 1行を優先すると、漢字＋読みは広域で表示件数が減ることがある。将来は**ズーム別に読み仮名を表示／省略**するオプションも検討。
- 「ひらがなのみ」は漢字より長くなりがち。仮名を勝手に省略しない。
- ラベル矩形内・区域内評価は概算であり、隣接町の境界付近では赤い判定でも読みやすい場合がある。
- 本試作は芦屋市のみ。西宮市の読みは別途 `Kussoon/nishinomiya` の正本と照合し、事実確認してから適用する。
- V2正式導入時は読みの表示切替を地図、検索、クイズ、復習の共通設定として展開する。世界の国名等では表記体系が異なるため、読み／別名／現地語表記を別属性として管理する。
- 今回の試作は既存の `/ashiya/`、他市、本番トップを編集しない。PRは未マージのまま公開判断を待つ。

## 2026-10-30 追加改訂：町域中心・全件表示を標準にする

ユーザーの実機スクリーンショットでは、楠町・平田町・親王塚町・月若町・西蔵町・南宮町などで、本来は町域中心に表示すればよい地名が端に大きくずれていた。理由は従来の `choosePositions(...,'avoid')` が、**文字枠9点の区域外に160点／点、ラベル同士の重なり面積×6**の罰則で候補を評価し、さらに `declutter` が重なったラベルを隠していたため。ユーザーは「少し重なっていても位置が見える方がよい。読めないときは拡大する」と明示した。

### 今回の変更

- **町域の幾何学的重心を初期のラベル中心に採用**。重心が区域外にある複雑形状だけ、内部の `polylabel` を代替点とする。芦屋市の59町名では、実際にすべての幾何学的重心が対応する区域内だった。
- **全59町名を最初から表示**し、通常はラベル重複を理由とする省略をしない。ユーザーが明示的に「重なるラベルを非表示（比較用）」をオンにした場合にのみ旧来の自動間引きを使う。
- **上下微調整なしが標準**。任意の上下調整は、元の中心から横方向に動かさず、ラベル同士の重なりがある程度大きいときのみ最大上下1.5文字を試す。境界線のはみ出しを減らすために勝手に端へ移動しない。
- 従来の `choosePositions(...,'avoid')` と `planVerticalNudges` を比較用の選択肢として維持。既存エンジンおよび公開されている `/v2/ashiya/labels.html` の動作は変えない。
- 漢字＋読み仮名の初期文字サイズを **16→18 CSS px** に変更。全表示形式で12～22pxに切り替え可能。
- 重なり件数・境界またぎ件数は「許容」の参考指標と明記し、エラーや非表示条件に使用しない。

### 予備計算（ブラウザ実測ではない）

文字幅を1文字≒フォントサイズとして、幅390px・全域・文字サイズ18px・「漢字＋読み仮名」を比較。

| 比較方法 | 表示される町名 | ラベル重複組数（概算） | 文字枠が境界をまたぐ名前（9点概算） |
| --- | ---: | ---: | ---: |
| 従来の重複回避＋間引き | 18 | 0 | 17 |
| 中心優先＋全件表示 | **59** | 356 | 58 |

数値は意図したトレードオフである。「重複0」「境界外0」は今後のV2の合格基準ではない。学習者が**拡大しながら全町名の位置を確認できること**を優先する。

中心優先ではたとえば、楠町の自動配置位置は `(859.3,934.0)` から幾何学的中心 `(833.7,951.7)` へ移る。西蔵町や親王塚町でも端への逃げが改善する可能性がある。ただし実ブラウザでの評価は未実施。

### 残る課題・実機確認

- 全域表示では多数の重なりが生じ、文字自体は読めないことがある。ズームで一つずつ確認できるか、ラベルが移動しないかをiPhoneで観察する。
- タップ・検索時に町名を確実に選べること、漢字／読み仮名／ひらがなの切り替え、デスクトップホイールB案などの回帰を確認する。
- 正式版では「全件表示」「拡大時のみ表示」「重複整理」を任意のモードとして提供する可能性があるが、**標準設定は本試作で実機評価してから決定**する。
- 町域の幾何学的中心だけでは離島・飛地・穴あき区域などに問題が起こり得る。現在の芦屋市の内部点確認を、他市・兵庫県へ拡張するときに再検証する。

## 2026-10-30 追加実験：くびれの自動補正＋縦長隣接町だけ上下調整

ユーザーが示した北部の複雑な町域では、ラベルを単に「幾何学的重心が区域内か」で判断しても、**中心が細いくびれ・区域境界のすぐ近くにあり、見た目の中心らしくない**ケースがあった。また、縦長の町域が左右に並び、ラベル同士が重なる場合には約半～1文字分の上下移動を試したい。

### 追加した「中心の安全補正」

1. 幾何学的重心と、区域境界から最も余裕のある内部点（Polylabel）を両方計算する。
2. 重心が**区域外**、または重心から境界までの距離がPolylabelの最大余裕距離の**26%未満**のときだけ補正する。
3. 重心からPolylabelへ向かう線分上を41候補（等間隔）で検査し、**区域内にあり、境界まで最大余裕距離の35%以上ある点のうち、重心に最も近い点**を選ぶ。入り組んだ多角形では線分途中が区域外になり得るため、各候補の所属区域・境界距離を再検査する。
4. 当てはまらない町は**中心を1pxも動かさない**。候補がなければPolylabelに退避する。

実データでは、芦屋市59町のうち「奥山」（重心の境界余裕11.6→補正後45.4 SVG座標単位）、「東芦屋町」（1.7→8.0）が補正対象。奥池町など通常の区域は元の重心を維持。これらは**位置の安全性を示す試算であって、実機の見た目の正解を保証するものではない**。

### 縦長の隣接町の自動微調整

- 両町とも南北方向に細長い（区域高さが幅の1.35倍超）、文字矩形が重なる、左右方向の中心が近いときだけ候補になる。
- 全ラベルを元の中心に配置してから、**他の全58ラベルとの重なり**を比較する。以前の「すでに配置済みのラベルだけで判定」は廃止。
- 上下に半文字／1文字の4候補を調べ、候補中心が元の町域にあること、既存より**重なる相手の数を増やさない**こと、移動で確実に改善することを満たす場合だけ採用。
- 全件表示を維持し、ラベル間の重複も境界線またぎも許容する。移動は地図の横方向に行わない。
- くびれ補正は地図形状だけで決まるため、ズーム時に揺れない。ただし上下移動は表示フォントサイズ依存のため、ズームにより候補が切り替わる可能性がある。実機で検証する。

### 試作ページの比較設定

- 位置：「中心優先＋くびれの安全補正」（初期値）／「単純な重心」／「旧式重複回避」
- 上下：「縦長の隣接町だけ自動調整」（初期値）／「調整なし」／「全般を上下調整」
- 文字18 CSS px、漢字＋読み、59件全件表示は引き続き初期値

### 近似予備検証（iPhone Safariの実測ではない）

幅390 CSS px、全域、漢字＋読み18px、等幅近似で比較。

| 方式 | 表示数 | 重なり組数 | 中心から移動したラベル |
| --- | ---: | ---: | ---: |
| 単純な重心・調整なし | 59 | 356 | 0 |
| 安全補正・上下調整なし | 59 | 355 | 2 |
| 安全補正＋縦長隣接町の自動調整 | **59** | **310** | **20**（安全補正2件と上下移動19件、重複対象あり） |

元の町域データ・読み59件は変更しない。正常な区域の中央をむやみに動かさないこと、境界外の重心でも自動的に区域内へ補正すること、縦長の合成町域で上下調整が起こることを回帰テストで確認。

### 限界

- 安全な中心は数学的な「最も見やすい文字位置」を完全には表さない。特殊な形状・穴あき・飛地は実際の地図を見て評価する必要がある。
- 強い重なりが残ってもラベルを非表示にするわけではない。読めない場合は利用者がズームする設計。
- 今回の変更は芦屋市V2の比較画面と共通の試作補助モジュールだけ。現行の西宮・芦屋等の正式公開ページには適用しない。

## 2026-10-30 追加：東芦屋町の左側だけが常にはみ出す問題への自動補正

iPhoneで芦屋市の読み仮名つき地図を拡大したところ、「東芦屋町」のラベルだけが、画面の拡大率を変えても町域の左端に寄り続けた。**ほかの58町は現行配置が良好**であるため、今回の修正では全体的な配置方針を変更しない。

### 原因

前回の `safeInteriorCenter` は、中心点が境界に近すぎる場合にPolylabel側へ補正するが、**同じ高さでの左右の余裕の非対称性は評価しない**。東芦屋町の補正後中心は約 `(628.9,824.2)`、その高さで左の境界まで約8.9、右の境界まで約34.3（SVG座標単位）。ラベルの文字幅は左右同じ程度に広がるため、左側の文字だけがはみ出しやすい。

### 今回の限定的な改善

- 選ばれた安全な中心点の高さで、実際の町域境界が水平線と交わる位置を取得し、中心点の左右の**連続した区域内の余裕**を計算する。
- 左右の余裕の比が**0.35未満**の極端な場合だけ、左右の余裕がほぼ等しくなる水平方向の位置を候補とする。
- **元の町域幅の15%以内の移動**、移動後も確実に町域内、境界からの余裕が**20%以上改善**という条件を満たす場合のみ採用。通常の町域中心は動かさない。
- 初期ラベルサイズや拡大率には依存しないので、基本の横方向のアンカーはズームによって変わらない。
- 画面全域の重複は引き続き許容し、すべての町名を最初から表示する。文字全体が絶対に町域内に収まる必要はない。

東芦屋町の中心は約 `(628.9,824.2)` → `(641.6,824.2)`。同じ高さで境界までの余裕は約 **左8.9／右34.3** → **左21.6／右21.6** になる。通常位置として改善できるのは今回の芦屋市データでは東芦屋町の1町のみで、残りの**58町名は座標不変**。奥山のくびれ補正や楠町の自然な中心も保つ。

### 回帰・評価

- 既存の幾何学・形状テスト（重心が外に出るL字多角形、奥山のくびれ、縦長町の上下微調整）を維持。
- 東芦屋町の左右の余裕、区域内中心、ほか58町の不変を追加テストで確認。
- 画面幅390px相当、漢字＋読み18px、1〜16倍に相当する複数の拡大率の等幅近似では、その他58町名の表示位置は変わらず、重なり組数も増えない。
- ただし、拡大率が低いと文字幅が町域の幅より大きくなるため、**境界またぎ自体をゼロにすることはできない**。それはユーザーが許容した設計である。
- iPhone Safariの実描画は公開後に再確認すること。

今回の変更対象は `v2/common/js/readable-labels.js`、`v2/tests/readable-labels.test.cjs`、本試験記録のみ。現行の西宮市・芦屋市正式版、地名・読み仮名データ、ページ内設定は一切変更しない。

## 2026-10-30：漢字＋読みの中心を漢字に固定・若葉町の片寄りを自動補正

### 実機指摘

1. **楠町**では、「漢字＋読み」の二行の縦方向中心が町域中心と一致するため、漢字自体が上に寄っていた。漢字のみの表示と**漢字の中心を完全に一致**させる。
2. **若葉町**では、右側の余白が広いのに、漢字ラベルが左境界をまたいでいた。「高浜町のラベルを避けて横移動した」わけではなく、現行の自動調整は**縦移動しか行わない**。原因は若葉町の局所的な左右偏りが0.35の閾値に届かず補正されなかったこと。

### 新しいルール（地名そのものは1行）

- 地図の町域アンカー（x,y）は**漢字1行の中心**。漢字＋読みモードでも漢字の `x`、`y` は同じ。
- 読み仮名は漢字中心より `0.90 × 漢字サイズ` 下に表示し、地名の主文字行を押し上げない。
- 上下微調整・必要時の衝突計算には**漢字の主行の矩形だけ**を用いる。読み仮名を含む全体の寸法は別の `visualWidth/visualHeight` として保存するが、配置・非表示の判断には使わない。読み仮名は添え字という位置づけで、読めない重なりは利用者の拡大に任せる。
- 診断画面の「重なり」「境界またぎ」は主文字についての近似値と明記する。

### 若葉町の補正

- 以前の東芦屋町への左右均等化と同じ汎用ルールを適用するが、**高さが幅の1.2倍より大きい縦長町**に限って、左右余裕の比の閾値を0.35から**0.50**にする。
- 従来の若葉町中心 `(801.8,1258.7)` では、同じ水平断面で左余裕約12.6・右余裕約26.6。補正後は `(808.8,1258.7)` で左右とも約19.6。
- 移動は町域幅の15%以内、修正後も区域内、境界からの距離が20%以上改善、の既存条件を維持。
- **芦屋市59件では、追加で動くのは若葉町のみ。他58件のアンカー座標は変わらない**。東芦屋町の既存補正も維持される。
