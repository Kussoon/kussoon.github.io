# Kussoon V2 共通設計案 v0.1（未確定）

作成：2026-10-30  
目的：芦屋市の町名と兵庫県の市町・区を同じデータ／処理モデルで表現し、世界・全国・丁目へ拡張する。**これは設計案であり、採用ライブラリや公開URLの変更を決定した文書ではない。**

## 1. 共有エンジンの責務

1. 地図の読み込みと描画
2. 地名ラベルの候補位置計算・重なり対策・拡大率調整
3. 地名・読み仮名・郵便番号等の検索、結果選択、地図へのフォーカス
4. 名前→場所／場所→名前のクイズ、正誤、採点、誤答復習
5. マウスホイールB案、地図クリック・タップ、ドラッグ、ピンチ、＋／−／全体表示
6. 属性情報（名産品等）を読み込むための追加パネル
7. 各地域の出典・ライセンス情報、版情報を表示するUI

地域データの取得方法と形状変換、HTMLの描画ライブラリは分離する。無理に全部Leafletへ、あるいは全部SVGへ統一しない。必要以上のサーバー・DB・大規模フレームワークを前提としない。

## 2. 地域階層とグループを分離

- `parentId`：行政上など定義された親子関係（例：日本→兵庫県→西宮市→町）。
- `groups`：非行政的な集合（関西、阪神間、市のコミュニティ、県の学習地域など）。複数所属を許可。
- `kind`：country/prefecture/municipality/ward/town/chome/learning-region 等。行政制度と学習区分を混同しない。
- `id`：名称とは独立した安定ID。異なる地域の同じ町名、改称、表示用の略称に対応。
- `geometryRef`：形状やアンカー情報の参照キー。地名IDと一対一と決めつけない。
- `aliases`、`reading`、`zipCodes`：検索用属性。出典と更新元を明確にする。
- `parentId` は単一親を原則とし、複数階層にまたがる生活圏は `groups` または別の関係データで表現する。

概念例（実データではない）：

```json
{
  "id": "jp-hyogo-nishinomiya",
  "name": "西宮市",
  "kind": "municipality",
  "parentId": "jp-hyogo",
  "groups": ["kansai", "hanshinkan"],
  "geometryRef": "municipality:28204",
  "reading": "にしのみやし",
  "aliases": [],
  "zipCodes": []
}
```

学習の出題単位と行政上の細分は別概念とする。兵庫県の49区域では神戸市を9区として出題し、名称表示では「神戸市」も補助表示する。市町村の合計数と地図に描くポリゴン数が必ず一致するとは限らない。

## 3. 形状・検索対象・ラベルを分離

```text
raw geometry  →  display geometry / zone anchors
                     ↓
region entities → map/search/quiz selection
                     ↓
          label candidates + overrides
                     ↓
             screen-space layout
```

- `geometry` はPolygon、MultiPolygon、必要に応じてPointアンカーを想定。面のない地名も検索対象として保持。
- 1つの地名IDに複数の図形を結びつけられる。複数ラベルの表示も可能にする。
- 町・丁目をまとめる処理は、単なる末尾文字列の削除だけに固定しない。正式名称と丁目の関係をデータで保持する。
- 地理データの原本・表示用加工物・人の補正を別ファイルに保持する。
- 補正キーは可能な限り `name` ではなく安定IDを使う。次回データ更新で座標だけ自動流用すると形状変更に追随できないため、差分検査を設ける。

想定されるファイル（採用前のイメージ）：

```text
/v2/data/ashiya/areas.topojson
/v2/data/ashiya/entities.json
/v2/data/ashiya/label-overrides.json
/v2/data/ashiya/config.json
/v2/common/js/labels.js
/v2/common/js/map.js
/v2/common/js/search.js
/v2/common/js/quiz.js
```

これらは未作成。最初のPRには空のデータやダミーJSONを置かない。

## 4. ラベル自動配置の実証設計

候補アルゴリズム：
- 重心 / SVGのBBox中心：速いが凹形・細長い区域で区域外になり得る。基準比較用。
- Polylabel：区域内部で境界から距離を確保しやすい。**文字幅や他ラベルの衝突までは解決しない**。
- 複数候補点＋スクリーン座標での衝突回避：ラベル幅・高さ・改行・表示優先順位を考慮。
- 地図ライブラリ内蔵のシンボル衝突処理：性能・導入負担の比較対象。

処理を3段階に分ける。

1. **形状側**：ポリゴン内の候補座標、各島・飛地の優先順位、候補点の余裕を事前計算できるようにする。
2. **表示側**：現在のズーム・画面幅・フォントの実測サイズに応じて文字の収まり・衝突を評価。改行、縮小、表示省略、拡大時表示を選ぶ。
3. **例外側**：どうしても解決しない箇所のみ人が補正。補正値は設定ファイルに保存し、更新時に再評価する。

「ラベル中心点がポリゴン内」と「文字全体が領域内」は異なるため両方を計測。隣接区域や図形外へのはみ出し、低ズーム時の表示省略も別指標にする。面がない地名は強制的にポリゴン内部へ移動させない。

**実証メトリクス**：対象地名数／描画面数／表示ラベル数／重複数／はみ出し数／非表示数／手動補正数／平均・最大処理時間。PC・iPhone・Android幅、初期・拡大表示を区別し、旧版との差分画像と数値を保存。採用閾値は実測後に決定。

## 5. 学習・クイズの共通設定

共通エンジンは次のモードを区別：
- `study`：ラベル付き学習地図
- `quiz-name-to-place`：名前→場所
- `quiz-place-to-name`：場所→名前
- `search`：地名検索・選択
- `details`：名産品や地域独自の補足情報

問題セットは `regionId` と `questionUnitKind`、任意の `groupId`、問題数などで選択する。画面ごとにコードを複製しない。問題の抽選・回答済み・初回正解・誤答履歴・再挑戦・結果画面を共通化する。

2026-10-02の [共通仕様案v0.2](https://github.com/Kussoon/nishinomiya/blob/main/common-learning-spec-draft.md) をUIの基礎資料とする。正誤色、誤答の赤表示持続、正解表示、44px程度の押せる範囲、進捗・採点・復習、如月先生の扱いなどは旧版との比較なしに変えない。

兵庫県の名産品や西宮のコミュニティ別学習は、必要なら地域別モジュールを追加できる構造にする。任意の詳細情報を必須項目にしない。

## 6. 利用者向け地域階層・公開URL・GitHubを区別

- **ナビゲーション**：世界→日本→都道府県→市区町村→町等をたどれる。関西・阪神間などは重複所属可能なグループとして表示。
- **公開URL**：原則として既存の `/hyogo/`、`/ashiya/` 等を維持。実証は `/v2/`、正式移行時の新URLは後で判断。
- **GitHub**：既存の6リポジトリを維持。サイト本体の `/v2/` を実証場とし、共通プログラム配信を先に固めてから将来の構成を決める。

構造案A=既存リポジトリ維持＋共通モジュール、B=段階的共通化＋新規地域から整理、C=一斉統合。現時点では**B案を暫定推奨**するが、GitHub Pagesの実際の公開設定・ルーティングと既存リンク・検索流入を確認するまで実行しない。

## 7. データ出典と公開品質

- CODHの町域・行政区域、宝塚・尼崎の独自補足、OSM、国土数値情報、名産品等はライセンスが異なる。
- 元リポジトリの `SOURCE_LEDGER.md` またはREADME・出典ページを確認し、データ移植時に帰属表示、改変内容、参照日を保持。
- 既存の町名検索データがブラウザ内で処理される設計を維持し、不必要に検索文字列を外部送信しない。
- 新規公開試験HTMLは `noindex`、Umami、共通7リンク。サイトマップへの登録は行わない。
- 「試験版」と明記し、未実装画面へのリンクを置かず、実機で検証していない挙動を合格扱いにしない。
- 本番移行時には、ソース互換、現行URL、検索・クイズの結果、ライセンス、アクセス計測の回帰試験を行う。
