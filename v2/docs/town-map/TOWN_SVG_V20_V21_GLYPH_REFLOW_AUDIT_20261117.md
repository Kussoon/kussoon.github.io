# 西宮市SVG町名マップ｜第20・21比較版 ラベル再配置と実文字測定の監査

調査日：2026-11-17（JST）  
正式基準：`v2/nishinomiya-town-study-c.html`（Leaflet C、変更なし）。  
比較対象：第19版（PR #558、Draft）、第20版（PR #563、Draft）、第21版（PR #564、Draft）。今回、正式版への切り替えは行わない。

## 調査方法と重要な発見

1. PR [#561](https://github.com/Kussoon/kussoon.github.io/pull/561)（main統合）で、C版とV19の地図投影座標、Leaflet tooltipの実枠、SVGラベルの基準点・位置補正キャッシュを操作順に追跡した。初期／読みON／文字125%／地域山口・上ヶ原／全域復帰で座標を取得。
2. PR [#562](https://github.com/Kussoon/kussoon.github.io/pull/562)（main統合）で、C版の古いTooltip外枠ではなく、名前テキストノードのDOM Rangeを使って実文字の矩形を取得した。SVG版の町名文字と読みも別に測定し、C版では実際に学習対象となるラベルに絞った。ラベル外枠が過去の幅を保持する状況があり、従来の外枠中心による比較だけでは見た目の評価として不十分である。
3. 実文字の監査でも、C版は初期表示では名前文字の右端付近が地理基準点に対応するのに対し、読み仮名の切替や地域再表示の後には名前文字の中心が基準点付近に移ることを確認した。最初の位置補正を持続させるだけではこの操作依存の変化を再現できない。
4. 第20版では初期モードと操作後の中央配置モード、直前に配置を更新した際の幅を使う文字倍率変化の計算を試作。C版との*町名の実文字*位置差を計測した。
5. 第21版ではWebKitのSVG tspan矩形取得方法を`getBBox/getScreenCTM`へ変更したが、検査の数値に改善は確認されなかった。実装に問題がないと断定せず、ブラウザ固有の文字レイアウトをさらに直接検証する。

## 未了の問題と次の技術検証

- C版で読みON→文字125％→読みOFF→地域変更→全域復帰と操作したとき、町名Glyphの位置が単純な固定幅／固定中心では説明しきれないケースが残る。実際の文字の左端・中央・基準点の変化を、CSS、LeafletのTooltip再配置タイミング、SVGの位置計算に分けて再調査する。
- WebKitでは町名の読み仮名行の矩形がC版より約12〜13pxずれる。第21版の`getBBox/getScreenCTM`への置換だけでは変化しなかったため、配置計算式と読み行の水平方向の基準を独立に検証する。
- 地域「上ヶ原」では特異な境界・分割形状を含み、表示位置最大差がV20/V21でWebKit約16〜19px、PCで約44px残る。C側の地域外DOM残骸を比較対象から外した後も残差があるため、個別表示状態で検証する。
- 町名直リンクと全域復帰時の差を詰めた後、C版とSVG版の実画像を目視照合し、全321町名／324ラベル／26地域とクイズ・全画面操作の回帰検査を実施する。
- iPhone Safari・PCの**利用者実機受入は未実施**。WebKitによるブラウザ自動検査はiPhone Safari実機合格を意味しない。

**判定：第20・21比較版は検証用途のDraftとして保持。第21版の文字矩形算出だけを単独で正式採用する根拠はない。正式Leaflet C版と旧比較版は保持し、未解決の差が残る状態で本番置換・実機受入依頼をしない。**
