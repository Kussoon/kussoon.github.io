# Kussoon V2 町名マップ 標準制作手順（草案 v0.1）

初版：2026-11-15／最初の検証対象：川西市（28217）

## 目的・優先順位
新しい市区町村のために地図エンジンを作り直さず、これまで全国V2・既存町名マップで確定した仕様・過去PR・回帰テストを継承する。**完成の判定はコードのテスト合格ではなく、データ検証＋実際の描画＋実機操作＋採用判断のすべてを要する。**

既存の確定仕様規則集と実装・過去PRが衝突する場合は、現在有効な仕様を調査・記録してから判断する。規則IDの対応は必ず実体を確認し、番号だけを根拠にしない。全国V2・既存5市の正式版は、個別の比較試作から無断で変更しない。

## 手順と完了ゲート
| 段階 | 作業 | 必須記録・合格条件 |
|---|---|---|
| 0. 基準固定 | ベースコミット、関連PR、規則集、共有モジュールを特定 | 参照SHA・使用ファイル・適用規則の照合表 |
| 1. 出典確認 | 公式名称、読み、CODH/e-Stat境界、基準年、ライセンスを取得 | 資料URL、取得日、年月日、正式境界との差分可能性 |
| 2. 元データ監査 | 属性・ID・区画数・座標・リング・重複・欠損・飛び地 | 統計ポリゴンと表示名を**別々に**集計。自動検査報告 |
| 3. 正規化 | 区域IDと名称の多対一対応、丁目、大字小字、読みの照合 | 未確認読みは未確認のまま。区をまたぐ同名は別ID |
| 4. 共通接続 | 自治体別JSONを共通ページに接続 | エンジン・操作コードの自治体別複製を原則禁止 |
| 5. 機械検証 | デコード、地図bbox、ラベルID対応、契約・回帰テスト | 正常系だけでなく、transform有/無、Polygon/MultiPolygon、異常形状も検査 |
| 6. ブラウザ検証 | 全体図・検索・町名フォーカス・拡大画面を視覚確認 | 320/390px、PC幅。**スクリーンショットと実表示の証拠**を残す |
| 7. 実機受入 | iPhone Safariなどで選択・ズーム・ドラッグ・ピンチ・ラベル確認 | 利用者の確認結果、未解決事項、合否記録 |
| 8. 正式採用 | URL・既存トップとの導線・noindex変更可否を判断 | 採用の明示的承認、変更箇所、ロールバック方法 |

## 実装上の原則
- データ：`v2/data/town-maps/<自治体コード>.json`
- 比較ページ：`/v2/town-map/?code=<自治体コード>`（比較試作中は `noindex,follow`）
- 既存の共有部品：`v2/common/js/label-engine.js`、`readable-labels.js`、`town-map-engine.js`、`v2/progressive-preview/map-viewport.js`
- 共通エンジンが利用する入力契約を確認し、必要なら**共通アダプターのテストを追加**する。
- 動作不良時、町名ごと・自治体ごとの応急補正より、原因と共通修正を優先する。
- データ、テスト、作業記録は変更と同時に更新する。

## 失敗を再利用できる知識へ
不具合には「再現手順→現象→根本原因→変更ファイル→再発防止テスト→ブラウザ再検証→採否」を残す。2026-11-15川西市の transform のないTopoJSONをデルタ加算した不具合を、典型的な失敗例として扱う（詳細は cases/28217-kawanishi.md）。

## 次の自治体への適用
川西市を基準例として、その後の三田市（28219）・川辺郡猪名川町（28301）・神戸市（28100・9区）では「データ・設定だけでの接続」を目指す。これが成立しない場合は例外を記録し、**一般化できる変更と自治体固有情報を区別**する。
