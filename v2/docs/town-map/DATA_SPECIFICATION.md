# Kussoon V2 町名データ契約（現行 v1 の記録＋次期検証項目）

2026-11-15時点の共通ページは `v2/data/town-maps/28217.json` を読み込み、`town-map-engine.js` へ `topo`・`kana` を渡す。以下は現行契約の記録であり、全自治体で検証済みという意味ではない。

## 現行の主要項目
- `schemaVersion`、`municipalityCode`、`municipalityName`、`boundaryYear`
- `source`：境界の名称・URL・DOI・ライセンス
- `readingSource`：読みの根拠・照合件数
- `topo`：TopoJSON（`objects.town.geometries` に統計区画、`arcs`、必要に応じて `transform`）
- `kana`：町名候補に対応する読み仮名照合データ

## 絶対に混同しない単位
1. **統計区画**：形状・一意の識別ID。1表示名に複数区画が対応することがある。
2. **表示地名**：検索・表示ラベルの基礎。川西市は191区画、182候補。
3. **住所上の町名・丁目・大字・小字**：公式資料での現行名称。統計区画と一致すると断定しない。
4. **読み仮名**：出典で確認できたものだけ公開し、未確認は推定しない。

川西市では `KEY_CODE` が一意ではないため、統計ポリゴンの識別には `R2KAxx_ID` を用いる。別自治体へ拡大する際はそれぞれの元データで一意性を検証する。

## 地図復元の重要な入力契約
- TopoJSONに `transform` がある場合：差分座標（デルタ）復号＋スケール/オフセット。
- `transform` がない場合：座標をそのまま使用。**絶対座標を累積加算してはいけない。**
- Polygon/MultiPolygonのリング階層と連結アークを正しく扱う。
- 元座標範囲と復号後bboxが一致することを監査し、投影後bbox・リング閉鎖・非有限値を検査する。
- 表示名が同じ複数ポリゴンは境界を保持したままラベル・検索単位としてまとめる。

## 未解決の設計課題
- 神戸市の区ごとのID衝突、区名＋町名の階層、表示名の二段・四段化
- 猪名川町の大字と小字の区別
- 出典年度が異なる境界の取り扱い
- label-engineとtown-mapアダプターのモデル順序・幅・可視範囲の整合
- GeoJSONなど別入力形式への展開時のスキーマ改訂

**現行JSONの構成を変更する際は、既存川西市データを用いた回帰テストと実ブラウザ表示比較を必須とする。**
