## A. すでに共通化済み：二重実装を作らない

| 領域 | mainで確認した共通契約 | 両市の現状／注意 |
|---|---|---|
| 町名・読みのSVGテキスト生成 | `KussoonTownSvgLabels.render` | 両比較版から呼び出す。要素の名前・読みを同じDOM方式で生成 |
| 複数区域とラベル候補 | `KussoonTownMultipartLabels.fromApproved/fromSvg` | 承認済み地点とSVG自動候補は **入力の種類** が違う。片方をもう片方で上書きしない |
| ラベル位置・文字サイズの更新 | `KussoonTownSvgLabelUpdate.update` | 宝塚は候補アンカーと可視性を渡す。西宮は `geometryUpdate` から確定済みviewport・C比較配置補正を呼び、`preserveVisibility` で既存状態を維持 |
| 可視性判定 | `KussoonTownSvgLabelVisibility.visible` | 宝塚の複数パーツ候補に使用。西宮の324ラベルへ独断で候補間引きを追加しない |
| クイズの状態と採点 | `KussoonTownSvgQuizState` | 両市から使用。問題順・進行・誤答・中断結果を共通契約で保持 |
| クイズ2の選択肢 | `KussoonTownSvgQuizChoices.select` | 両市から使用。隣接・地域・距離は入力だが、入力を作る実装は異なる |
| クイズ選択肢UI／地域読み順 | `KussoonTownSvgUI` | 両市から使用 |
| 地図倍率操作の基本部品 | `KussoonTownSvgCore.zoomBy`、`KussoonTownSvgViewport.fitBounds` | 共通部品は存在する。表示範囲の決定とreset等の配線は未統一 |

**結論：** ラベルを「生成する」「更新する」共通部品は既にある。次に同名の市別更新関数を増やしたり、文字生成や採点を新規実装する必要はない。

## B. 市別の画面側に残っている責務：統一対象候補

| 優先 | 責務 | 西宮比較版 | 宝塚比較版 | 次の共通化方針 |
|---|---|---|---|---|
| **P1** | 町域の読み込み・ジオメトリを画面へ渡す | TopoJSON形状、地域所属・境界例外、地理投影の座標系 | 元SVGパス・viewBox、穴と複数パーツ、独立候補 | **入力アダプターの出力契約** を先に統一し、座標系・穴・複数パーツ・複数地域所属を失わない。無理に元データを統一形式へ書き換えない |
| **P2** | SVG町域描画と選択・ハイライト | `KussoonTownSvgRender.render` と `renderLayers` | D3 path joinと `render` 内の個別イベント | 地図要素と選択イベントの入力を共通化。町名に依存した描画分岐は作らない。西宮の岡田山等の具体的な注記はデータ入力へ |
| **P2** | ズーム・全体表示・地域選択 | 投影と地域境界に合わせた `draw/regionFit/reset`、V34の位置補正連動 | SVG viewBox、`fit/showCommunity/reset` | 地図座標→画面座標の責務とfit/リセットを分離。ズーム直後のラベル補正・地域状態の保持を厳密比較 |
| **P3** | クイズ画面・点滅・中断／復習 | `startQuiz/loadQuizQuestion/finishQuiz` 等でDOM・タイマーを制御 | `startQuiz/loadQuestion/finishQuiz` 等でDOM・タイマーを制御 | **採点は既に共通**。残る状態とUIの接続だけを抽出し、`R-TOWN-34/35` の中断案内再発を防ぐ |
| **P3** | 隣接・距離の材料 | TopoJSONを共通 `KussoonTownSvgQuizGeography.create` に渡す | SVGパスの辺抽出とviewBox矩形で近接候補を用意 | `KussoonTownSvgQuizChoices.select` を維持し、隣接/距離の正規化入力契約を作る。地理的な意味・距離精度が違うため数値の一律置換はしない |
| **P4** | UIボタンの配線・全画面・案内文 | ページ内に直接記述 | ページ内に直接記述 | 縦並び右下・全画面右上などの確定仕様と状態遷移を共通化。データに属する地域名・町名は入力で指定 |

**留意：** 表示見た目が同じでも、データ座標系やラベル候補の性質は異なる。現行のイベント配線の差を、そのまま「自治体専用の正式仕様」として固定しない。

## C. 自治体ごとに保持すべき「データ」であって、共通化して消すべきではないもの

- 町名・読み仮名・地域名と読み・町名の地域所属・複数地域所属
- 西宮市の321町名／324地点、確定済み微調整、上甲東園の地域境界、岡田山の注記、山口・名塩の複数地点ラベル
- 宝塚市の125町名／20地域、穴・飛び地・切畑等の複数区域、136候補の位置・候補となった独立ポリゴンの面積
- 元TopoJSON／SVGの形状と参照関係。変換の結果と元データの対応を全件照合する必要がある

**検査用の期待件数** は自治体入力値として保持する。自治体名で if 分岐する共通エンジンを作ったり、全市に321件/324件等を固定したりしない（R-TOWN-00/06/44）。

## E. 以後の順序（採用済みの機能を飛ばさない）

1. **最優先 P1：入力アダプターの監査と比較契約**。TopoJSON/SVGを、町名・所属・形状/穴・複数ポリゴン・表示座標・ラベル候補へ正規化する共通の「出力の型」を監査する。元ファイルと全件照合。先に正式画面を書き換えない。
2. **P2：共通SVG描画・fit/地域切替の比較試作**。入力契約を利用し、既存の西宮・宝塚の比較ページと、テキスト矩形・町域パス・選択/クイズ遷移を厳密に比較する。V34のラベル補正を保持。
3. **P3：クイズ画面/点滅イベントの統一**。共通採点を維持し、中断→クイズ切替の再発テストと誤答/再挑戦全件を通す。
4. **P4：UIとナビゲーションの共通化**。地図内のボタン、全画面、スマートフォンの操作、直リンク、サイトフッターを回帰比較する。
5. 各段階で **独立比較→同条件での自動回帰→差分説明→ユーザー採否** を守る。既存の正式入口は、別途明示の切替指示まで維持する。
