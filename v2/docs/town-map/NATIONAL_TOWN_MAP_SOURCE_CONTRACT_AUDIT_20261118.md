# 全国町名マップ｜SVG・TopoJSONの共通データ契約 比較試作記録

- 唯一の規範：`TOWNMAP-SSOT-001`（R-TOWN-00、01、02、04、05、06、10、11、13、30、42、44）
- 実装目的：市区町村ごとに読み込み方式を別ロジック化せず、入力形式に応じた**共通アダプター**で統一する。仕様書は増やさない。
- 既存採用：西宮市SVG V34（321町名・26地域）は`town-svg-data-contract.js`の`load()`を使用。宝塚市125町名・20地域は`town-svg-source-adapter.js`で元SVGを読み込み（PR #597まで）。
- 変更：全国共通`KussoonTownSvgDataContract.loadUnified(manifest,deps)`を追加。入力は`sourceFormat:'svg'|'topojson'`。返却は`records:[{name,reading,communities,geometry}]`、`regions`、`raw`という同一インターフェイス。
- SVG：既存ソースアダプターで元HTMLと町名台帳を照合し、**SVG pathのd文字列をそのまま保存**。飛び地・内側の穴・形状の描き換えをしない。
- TopoJSON：採用済み`load()`をそのまま呼び出し、GeoJSON Featureの参照を失わずラップする。台帳にない地域の推定や読み仮名の創作をしない。西宮市の上甲東園等の地域例外は現行の共通Membership処理と正規データに残す。
- 宝塚の独立比較版：`v2/takarazuka-town-svg-unified-source-20261118-pilot.html` では`loadUnified()`経由で得たデータを既存表示エンジンに渡す。描画・ラベル・クイズ・ボタンは変更しない。

## 検査条件

1. 共通契約の単体検査でSVG複数パーツ・TopoJSONフィーチャー参照の無変更、件数・読み・重複・地域不一致の拒否を確認。
2. PC Chromium1280とWebKit390/320で旧・新比較版の**全125町域pathの文字列、136ラベル候補のアンカー、地域メニュー21件**の完全一致。
3. 同じ3環境で125町名×クイズ1・2の全問正答、20地域、誤答・再挑戦・中断の回帰を確認。
4. 西宮市の既存V34と`load()`を破壊しないこと。全国V2の検査を継続。

**制限**：これは共通の「入力契約」が作れたかという検証です。両市で描画やラベル生成の実装まで一本化されたことを意味しません。TopoJSONとSVGを無理に同一図形形式に変換して座標を変えることもしていません。新しい自治体でも市名に依存した処理が不要になるかは、引き続き検証します。
