## 3. 川西市の現行不適合（コードで確認）

1. `town-map-engine.js:renderLabels` は全国版 `planAdaptiveLabels` と `selectPriorityLabels` を町名に適用し、2倍以上では一律に重複許容する。**利用者提出の実機画像では初期縮尺の広いラベル欠落と拡大時の過密が発生。T03 不合格。**
2. `town-map-engine.js:select` は `.active` のハイライトと任意の範囲移動にとどまり、西宮B/Cの0.5秒点滅・再タップ停止を実装していない。T07 の正式な採否は別途定義。
3. `town-map/index.html` は `code` を読み込んで表示するが、`v2/geography/data/hierarchy.json` の川西ノード登録・町名用 `townData`・往復URL接続は未実装。T11 未達。
4. **再調査で訂正：** `town-map/index.html` は `town` パラメータを検索欄へ設定する一方、読み込んだ `town-map-engine.js:create` の末尾にも `town` を読み、名前が完全一致すれば `select(town,true)` で町名を自動選択・フォーカスする処理が存在する。第2次の『未実装』判定は誤り。**コード上は実装済み／実ブラウザ動作と階層からの導線は未検証**。入力処理の二重化は設計整理候補。
5. 川西の既存テストはTopoJSON復号と静的契約＋全国版の回帰を主に検査する。**川西画面自体を、全体・南北・ズーム・フォーカスで実測するテストがない**。T14 未達。

## 4. 6市目追加に伴うテスト移行（実ソースを確認）

`v2/geography/test-hierarchy.cjs` は5市固定の次の契約を持つ。

- `cities.length === 5`、`config.nodes.length === 8`、`config.version === '0.6.0'`。
- 既存5市の `expectedCount` 合計を **721** に固定。
- 5市のID、親子関係、既存URL、3種の `focusMode`、読みと特殊例外を検証。
- 元5市のリポジトリが配置されない環境では、一部照合を `NOTE ...省略` とする。CIで5市の元リポジトリが揃っているかも併せて確かめる必要がある。

**6市への変更時のルール：**

1. 既存5市のID・町名数321/125/140/76/59・リンク・特殊例外を「後方互換」の契約として残す。
2. `world`→`jp`→`jp-hyogo` の親子を維持し、川西（市コード28217）のノードを追加。合計 **6自治体・9ノード** にする。
3. `townData` に新しい `sourceKind`（TopoJSON＋読み＋表示名/境界の対応）を用いるなら、既存の3入力方式と3遷移方式を壊さず、明確なデータ契約・読み込み・検索・町名選択を用意する。
4. 川西の182件は2020年統計表示名候補。**721件に単純加算した903件を正式な町名総数としない**。正式な町名索引として採用する基準を照合してから件数テストを確定。
5. 既存5市往復と新しい川西往復の双方をWebKit/Chromiumで検査し、ユーザーのiPhone Safari実機受入後に正式版判断。
6. テストで検出された旧固定値は、既存5市の後方互換性を維持する形に改訂し、数を無制限に許容するだけの弱い検査にしない。
