開始日：2026-10-30。対象は `/v2/national/` のみです。正式版、既存の47都道府県別ナンバープレートページ、各市町村記憶ゲームには変更を加えていません。

境界データは SmartNews SMRI `japan-topography` の、2021-01-01 国土数値情報を約1%に簡素化した都道府県別 TopoJSON 8ファイルです。

原データ・処理： https://github.com/smartnews-smri/japan-topography/tree/main/data/municipality/topojson/s0010

**重要：2021年の簡略化した境界線は正式版に使用しません。** 正式版の準備段階では2026年版の現行区域へ更新し、境界未確定・島しょ・海岸線・市町村の設置廃止、原データの利用条件や国土地理院承認要件を別途検証してください。今回のデータは配置アルゴリズムの検証用です。

## 設計

1. **座標の共通化：** 都道府県をまたいでも緯度経度を保持し、同じ投影関数でひとつのSVG座標に変換します。地域を追加する際、県ごとに別の縮尺や画像へ作り直しません。
2. **行政区域のID：** 5桁の `N03_007` を正本とし、同名の市町村が別県にあっても混同しません。区域IDは `都道府県2桁:市区町村コード5桁`。
3. **郡名を含む町村名：** N03_003 が「郡」で終わる場合だけ、地図ラベル・検索候補・選択表示に郡名を付けます。地図上では `川辺郡／猪名川町`、`神崎郡／神河町` の2段表示とし、正式名称（`川辺郡猪名川町`）と元の `N03_004`（短い町村名）を分けて保存します。神戸市などの「市名／区名」も同じ共通部品を使用します。文字の重なり判定は、つなげた1行ではなく表示する2行分の最大幅・合計の高さで行います。
4. **政令市モード：** `catalog.json` の `designatedCities` は行政上の親市コードの辞書です（*町名ラベル位置の手動補正ではありません*）。`municipality` モードは同一市の区を TopoJSON 共有Arcで統合、`ward` は行政区を保持します。N03_003には郡名も入るため、郡は統合しません。
5. **ナンバープレート表示：** `catalog.json` の `plates[].municipalityCodes` が対象区域の集合を表します。県別ファイル名・描画済み輪郭に依存しません。県をまたぐ場合も1グループで描画し、データから1つのラベル中心を求めます。
6. **ラベル配置：** 共通 `label-engine.js`、`readable-labels.js`、`collision-refinement.js` を再利用。町名固有の座標リストは用意しません。全域では重なりが残る場合があるため、画面倍率ごとに測定します。
7. **データと描画の分離：** GISの更新は `data/national/<基準年>/<都道府県コード>.topojson` に局所化し、表示側はJSONカタログを参照します。

## 全国47都道府県への拡張方針

- 最初の2021年ベースの試験は8府県。今後は新しい国土数値情報 N03（2026年1月1日時点の最新版が公開されています（https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-N03-2026.html））を利用し、47都道府県の境界データの更新と行政区域コード照合を行います。
- 元の47都道府県別ナンバープレートHTML（`/driving/vehicleregistrationplates/region/`）は現行公開版として保持します。
- 各地域名表示と市区町村コードを対応付けた、基準日つき全国ナンバー地域台帳を別途整備します。富士山は「県境をまたぐ例」の最初のテストケースです。
- 全国一括TopoJSONを読み込ませるのではなく、ビューの表示範囲に合わせて府県データを遅延読込みし、モバイルでの応答速度を維持します。
- 次の必須試験は、府県境界付近の描画、政令指定都市統合、島しょのポリゴン、巨大な市・細い町・飛地での配置、ラベルの全件表示と縮尺での重なり、実機iPhoneの操作です。

## 検証条件と既知の制約

- 関西：`/v2/national/?area=kansai` で198市町村／245区単位の切替を検査。
- 富士山：`/v2/national/?area=fuji` で山梨7＋静岡5の一括着色と12区域のコード一致を検査。
- 検索は現段階では漢字の部分一致とコード一致。**読み仮名検索は今後共通の読みデータが揃ってから**実装します。
- 全国V2の初期表示文字は15px、最大拡大時は17pxを目安にした試験値です。西宮市の町名V2（16px）とは区別します。
- **ナンバープレート表示は、地域名が地図を見ただけで分かる表示を優先します。** 現在の富士山実験では対象12市町村を一括着色して「富士山」を1つの地域名ラベルとして表示し、市町村名も位置確認のため残します。市町村をタップして追加情報を表示する操作は無効にします。検索は市町村が富士山ナンバー対象か調べるために残します。
- 青色は「ほかのナンバー名が確定した区域」ではありません。この試験では富士山ナンバー以外の地域名をデータ化していないため、青色は**ナンバー地域未収録**を意味します。
- 山梨・静岡の2021年データには静岡市3区と浜松市7区が含まれます。市単位で統合すると62市町村、区単位だと70区域。浜松市は2024年に区再編されているため、現在の区名ではありません。
- 現段階で地図に表示する「富士山」はナンバープレート地域の単一ラベルです。境界線の端部が簡略化により県境をまたぐ部分で完全一致しない可能性があります。
- 正式ページの更新・置換はユーザーの別途承認を必要とします。

## タッチ操作と選択表示

全国市区町村モードでは、選択した区域の強調表示と、指で触れただけの状態を明確に区別します。SVGの `:hover` はマウス・トラックパッドなどが使える端末だけに適用し、iPhoneでは指を離した後に濃色の輪郭線が残らないようにします。キーボードの `:focus-visible` は維持します。ナンバープレートモードの地図は引き続き非タップ式です。

## 2026-10-30 追加：文字箱の区域内適合度（全国V2限定）

- 共通モジュール `v2/common/js/region-fit.js` を追加。地図表示の漢字1段だけでなく、郡名／町村名・市名／区名の2段ラベルも、**全体の文字矩形**で位置判定します。
- 5×5点でラベル矩形の内部を標本調査し、配置先の自治体内にどれだけ収まるかを推定します。中心点1か所だけの内外判定ではありません。
- 中心位置、上下左右・斜めの相対移動候補、区域形状の広い部分の候補を、地名や市町村コードに依存せず生成します。ラベル間の重なり件数を増やさない場合だけ移動し、すでに十分収まるラベルは移動しません。
- 198／245区域を含む**全国V2の市町村・区モードで拡大4倍以上**のときだけ有効化しています。全域の縮小表示では同時表示に収まらない町が多いため、従来の配置を維持します。ユーザーが実機で合格を確認した**富士山ナンバーの地域表示は変更しません**。
- 地図の診断欄に「文字箱の区域外相当量（推定）」の改善前後を追加しました。実ブラウザのSVG文字の輪郭ではなく、文字矩形の標本評価値です。
- 回帰テスト：`node --test v2/tests/region-fit.test.cjs`。穴のある形状、飛地、既存配置の保持、重なり件数の非増加を検査します。
- この工程では**飛地への追加ラベルはまだ実装していません**。次工程で、同名の分離した区域の大きさ・画面上の面積・表示倍率を使い、重複ラベルを自動生成する規則を別途検証します。
- エンジンが全ての区域で文字箱の100％収容を保証するものではありません。形状が細い・狭い、文字数が長い等のケースでは、無理に区域外へ遠く移動させず、改善できる範囲に限定します。

## 2026-10-30 追加：ラベル四辺の境界余白評価

- 既存の25点（5×5）判定は、文字の外周だけが境界を越える場合に見落としがありました。文字の矩形の上下左右それぞれ5点、合計20点（角は重複）を評価し、自治体の境界までの**符号付き最小距離**を追加しました。
- 追加の境界余白は、地名に依存しない `region-fit.js` の共通機能として実装。郡名／町村名・政令指定市名／区名の2段ラベルの全体矩形にも同じ規則を適用します。
- 全国の市区町村モードでは従来の5×5適合度処理を最初に適用し、**6倍以上の拡大時だけ**新しい余白改善処理を重ねます。4倍以上・6倍未満は以前の配置を維持します。広域全域表示と富士山ナンバーモードは変更しません。
- 文字箱内部の収まり具合を悪化させず、重なりを増やさない候補だけ採用します。画面の端で表示対象が切り替わって重なりが増える場合は、追加調整を巻き戻します。
- 診断欄には「境界近接ラベル」の改善前／改善後も表示します。これは実際のSVG文字輪郭ではなく、文字全体の推定矩形の安全余白です。
- 実データの関西198市町村で、串本町・米原市・神河町・福崎町・猪名川町・奈良市・大阪市の各周辺を4・6・8・10・12・14倍の42条件で比較。既存版と比べて**文字箱の区域外相当量・ラベル重なり件数のいずれも悪化なし**（ジオメトリ計算上）。
- 代表結果：8〜14倍の米原市は右方向、6倍の神河町は下方向に寄ります。串本町は区域形状が複雑なため、倍率によって最適方向が異なり、常に下に移るわけではありません。個別座標の例外は追加していません。
- 回帰テスト：`node --test v2/tests/region-fit.test.cjs` に、5×5の内部標本では見逃す細い境界越え（上下・左右）を追加しています。
