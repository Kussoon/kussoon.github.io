境界データは SmartNews SMRI `japan-topography` の、2021-01-01 国土数値情報を約1%に簡素化した都道府県別 TopoJSON 8ファイルです。

**重要：2021年の簡略化した境界線は正式版に使用しません。** 2026年時点の現行区域へ更新する際、境界未確定・島しょ・海岸線・市町村の設置廃止、原データの利用条件や国土地理院承認要件を別途検証してください。今回のデータは配置アルゴリズムの検証用です。

## 設計

1. **座標の共通化：** 都道府県をまたいでも緯度経度を保持し、同じ投影関数でひとつのSVG座標に変換します。地域を追加する際、県ごとに別の縮尺や画像へ作り直しません。
2. **行政区域のID：** 5桁の `N03_007` を正本とし、同名の市町村が別県にあっても混同しません。区域IDは `都道府県2桁:市区町村コード5桁`。
3. **政令市モード：** `catalog.json` の `designatedCities` は行政上の親市コードの辞書です（*町名ラベル位置の手動補正ではありません*）。`municipality` モードは同一市の区を TopoJSON 共有Arcで統合、`ward` は行政区を保持します。N03_003には郡名も入るため、郡は統合しません。
4. **ナンバープレート表示：** `catalog.json` の `plates[].municipalityCodes` が対象区域の集合を表します。県別ファイル名・描画済み輪郭に依存しません。県をまたぐ場合も1グループで描画し、データから1つのラベル中心を求めます。
5. **ラベル配置：** 共通 `label-engine.js`、`readable-labels.js`、`collision-refinement.js` を再利用。町名固有の座標リストは用意しません。全域では重なりが残る場合があるため、画面倍率ごとに測定します。
6. **データと描画の分離：** GISの更新は `data/national/<基準年>/<都道府県コード>.topojson` に局所化し、表示側はJSONカタログを参照します。

## 全国47都道府県への拡張方針

- 最初の2021年ベースの試験は8府県。今後は新しい国土数値情報 N03（2026年基準のデータも公表されています）を利用し、47都道府県の境界データの更新と行政区域コード照合を行います。
- 元の47都道府県別ナンバープレートHTML（`/driving/vehicleregistrationplates/region/`）は現行公開版として保持します。
- 各地域名表示と市区町村コードを対応付けた、基準日つき全国ナンバー地域台帳を別途整備します。富士山は「県境をまたぐ例」の最初のテストケースです。
- 全国一括TopoJSONを読み込ませるのではなく、ビューの表示範囲に合わせて府県データを遅延読込みし、モバイルでの応答速度を維持します。
- 次の必須試験は、府県境界付近の描画、政令指定都市統合、島しょのポリゴン、巨大な市・細い町・飛地での配置、ラベルの全件表示と縮尺での重なり、実機iPhoneの操作です。

## 検証条件と既知の制約

- 関西：`/v2/national/?area=kansai` で198市町村／245区単位の切替を検査。
- 富士山：`/v2/national/?area=fuji` で山梨7＋静岡5の一括着色と12区域のコード一致を検査。
- 検索は現段階では漢字の部分一致とコード一致。**読み仮名検索は今後共通の読みデータが揃ってから**実装します。
- 山梨・静岡の2021年データには静岡市3区と浜松市7区が含まれます。市単位で統合すると62市町村、区単位だと70区域。浜松市は2024年に区再編されているため、現在の区名ではありません。
- 現段階で地図に表示する「富士山」はナンバープレート地域の単一ラベルです。境界線の端部が簡略化により県境をまたぐ部分で完全一致しない可能性があります。
- 正式ページの更新・置換はユーザーの別途承認を必要とします。
